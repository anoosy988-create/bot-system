=========================================================
  CYPHER SECURITY  —  دليل الرفع الصحيح
=========================================================

  ⚠️  قبل أي شي: غيّر التوكين.
      التوكن والمفتاح و Mongo URI اللي كنّا مستخدمين صاروا
      مكشوفين. روح Discord Developer Portal → Bot → Reset Token،
      و MongoDB Atlas → Database Access → غير كلمة المرور.
      بعدين حط القيم الجديدة في .env.


---------------------------------------------------------
  1) بناء حزمة الرفع
---------------------------------------------------------

    في مجلد المشروع:

        npm run build

    ينتج:  dist/bot.zip

    السكربت بيعمل 3 حاجات مهمة:
      • بيتأكد إن dashboard/server.js و dashboard/public/ داخل الحزمة
        (ده بالظبط الخطأ اللي كان بيكسّر البوت كله).
      • بيحوّل .env إلى .env.example بدون القيم.
      • بيفشل العملية إذا الحزمة ناقصة — فمايرفعش ناقص.


---------------------------------------------------------
  2) الرفع على WispByte / Pterodactyl
---------------------------------------------------------

  1. ادخل File Manager وروح لمجلد:

         /home/container

  2. احذف كل الملفات القديمة (index.js القديم، أي مجلد فرعي مثل
     bot-system-main/ أو Server-Security/) عشان ما يصير تعارض.

  3. ارفع dist/bot.zip وفك الضغط **داخل /home/container مباشرة**
     — مو داخل مجلد جديد.

  4. لازم يكون الشكل كذا بالضبط:

         /home/container/
           ├── index.js              <-- مباشرة، مو داخل مجلد
           ├── package.json
           ├── tickets.js
           ├── build.js
           ├── .env                  <-- ترفعه يدوي (انظر خطوة 3)
           └── dashboard/
                 ├── server.js       <-- 🔴 هذا اللي كان ناقص
                 └── public/
                       ├── index.html
                       ├── app.js
                       └── style.css

  5. Settings → Startup:
         JS_FILE = index.js

  6. شغّل السيرفر.


---------------------------------------------------------
  3) ملف .env
---------------------------------------------------------

  .env ما موجود بالحزمة (مقصود). ارفعه يدوياً في /home/container:

         DISCORD_TOKEN=xxxx
         CLIENT_ID=xxxx
         CLIENT_SECRET=xxxx
         MONGO_URI=xxxx
         SESSION_SECRET=.any-long-random-string
         OWNER_IDS=your_discord_id

  SESSION_SECRET ولّد واحد:

         node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

  DASHBOARD_REDIRECT_URI و DASHBOARD_URL اتركهم فاضي —
  البوت يكتشف رابطه تلقائياً من أول طلب.

  ملاحظة: CLIENT_ID اختياري — لو ما حطيته البوت ياخذ آيدي تطبيقه
  من عند ديسكورد لحاله. الوحيد اللي لازم يت موجود هو CLIENT_SECRET،
  وبدونه الداشبورد يفتح للكل بس ما يقدر أحد يسجّل دخول.
  افتح /api/auth/status في المتصفح — يرد لك وش الناقص بالضبط.


---------------------------------------------------------
  3.5) مين يقدر يسوي إيه بالداشبورد
---------------------------------------------------------

  • الداشبورد مفتوح للكل: أي حساب ديسكورد يقدر يدخل بضغطة وحدة.
  • كل واحد يشوف سيرفراته هو فقط (اللي عنده فيها Admin أو رتبة
    ستريتر)، ويشوف على كل سيرفر: البوت داخله ولا لا.
  • إعدادات الحماية (حدود + عقوبات + حماية الاختصار) = راعي البوت
    بس (OWNER_IDS). الباقي يدخل ويشوف بس ما يقدر يعدّل.
  • باقي التبويبات (ترحيب، تكتات، سجلات، إيمبد، إجراءات إدارية)
    متاحة لكل إدمن عادي مثل ما كانت.


---------------------------------------------------------
  4) تسجيل رابط الداشبورد في Discord
---------------------------------------------------------

  بعد ما السيرفر يشتغل وشوف رابطه (مثلاً
  https://cypher-security.onrender.com) :

  Discord Developer Portal → OAuth2 → Redirects → Add a redirect:

         https://<your-domain>/api/auth/callback

  ⚠️ اللازم يتطابق **حرفياً** (نفس البروتوكول، بدون / في الآخر،
     بدون www). ما يسجّلش / — لازم /api/auth/callback.

  هذا هو السبب الأكثر شيوعاً لـ "الداشبورد يفتح但 يطلع خطأ".


---------------------------------------------------------
  5) بعد نجاح التشغيل — امسح الحزمة
---------------------------------------------------------

         rm dist/bot.zip

  (ما فيها أسرار، بس ما داعي تبيّنها)


---------------------------------------------------------
  6) استضافة Render
---------------------------------------------------------

  موجود ملف render.yaml جاهز:
     New → Blueprint → اختر المستودع → املأ القيم.

  ⚠️ خطة Render المجانية توقّف السيرفر بعد خمول، وديسكورد
     بيوصل رسالة "disconnected". لازم خطة مدفوعة، أو
     UptimeRobot يعمل ping كل 5 دقائق (حل مؤقت).


---------------------------------------------------------
  7) التحقق السريع (Console)
---------------------------------------------------------

     ls -la /home/container

  لازم تشوف index.js و package.json و .env في نفس السطر،
  ومجلد dashboard موجود.

     node -e "require('path');require('fs').existsSync('./dashboard/server.js')&&console.log('dashboard OK')||console.log('dashboard ناقص!')"

     curl -s localhost:3000/healthz

  لازم يرجّع ok. لو رجّع 404 أو ما في رد — الداشبورد مو mounted،
  راجع خطوة 4.

  وشوف لوق السيرفر. لازم تلقى:

     ✅ Web server
     ✅ Dashboard

  لو لقيت "Dashboard unavailable" بدالها، البوت بيشتغل بس
  الداشبورد لا — وهذا أفضل من ما يموت البوت كله.


---------------------------------------------------------
  8) أوامر Slash
---------------------------------------------------------

  الأوامر تتسجّل تلقائياً عند تشغيل البوت (Guild instantly).
  لو ما ظهرت، جرّب:

     node tools/check-commands.js

  يطبع حجم كل أمر. ⚠️ Discord الحد الأقصى 4000 حرف للأمر الواحد.
  لو أي أمر عدّى 4000، فشل تسجيل **كل** الأوامر — وهذا اللي كان
  يخلّي /protect و /ticket ما تظهر أصلاً.


---------------------------------------------------------
  9) أوامر مفيدة
---------------------------------------------------------

     npm start              تشغيل البوت
     npm run build          بناء حزمة الرفع
     npm test               اختبارات التكتات
     npm run check:commands فحص أحجام أوامر Slash
     npm run verify         الاثنين مع بعض
